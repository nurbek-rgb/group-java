# Краткое руководство для защиты MVP

## Что делает программа

Пассажир создаёт заказ с двумя координатами. Заказ попадает в потокобезопасную очередь. Несколько диспетчерских потоков могут брать заказы одновременно. Для каждого заказа программа находит ближайшего свободного водителя, рассчитывает цену и записывает поездку в SQLite.

## Как показать программу

1. Открыть `TaxiDispatchSystem.java` и запустить метод `main`.
2. Показать в консоли назначенных водителей и цену.
3. Показать созданный файл `taxi_dispatch.db`.
4. Открыть `reports/trips.csv`.
5. Запустить `.\mvnw.cmd test` и показать 10 успешно пройденных тестов.

## Главные места в коде

- `main` — полный демонстрационный сценарий.
- `User`, `Passenger`, `Driver` — абстрактный класс и наследование.
- `PricingStrategy` — интерфейс; `StandardPricing` и `SurgePricing` показывают полиморфизм.
- `Repository<T>` — собственный generic-интерфейс.
- `DriverRepository` и `TaxiDao` — работа с SQLite через JDBC.
- `TaxiDao.assignDriver` — транзакция: водитель становится занятым, заказ обновляется и создаётся поездка. При ошибке выполняется `rollback`.
- `DispatcherService` — `BlockingQueue`, `ExecutorService` и выбор ближайшего водителя через Stream API.
- `Driver.tryReserve` — `ReentrantLock` не позволяет дать одному водителю два заказа.
- `ReportService` — `map`, `groupingBy` и CSV.

## Объяснение сложной части

Если два диспетчерских потока одновременно увидят одного свободного водителя, метод `tryReserve()` закрывает проверку статуса блокировкой. Первый поток меняет статус на `BUSY`, а второй получает `false` и ищет другого водителя. Дополнительно SQL-команда обновляет только водителя со статусом `AVAILABLE`.

## Что отвечать про SQLite

SQLite не требует отдельного сервера. JDBC-драйвер открывает файл `taxi_dispatch.db`. При первом запуске программа выполняет `CREATE TABLE IF NOT EXISTS`. Назначение водителя выполняется одной транзакцией с `commit` или `rollback`.

## Обязательные технологии

| Требование | Где показано |
|---|---|
| ООП | `User`, наследники, интерфейс стратегии, enum |
| List, Set, Map | список водителей, активные водители, карта заказов |
| Generics | `Repository<T>` |
| Stream API | поиск ближайшего и `groupingBy` |
| SQLite + JDBC + DAO | `Database`, `DriverRepository`, `TaxiDao` |
| Транзакция | `TaxiDao.assignDriver` |
| CSV | `ReportService.exportCsv` |
| Многопоточность | `BlockingQueue`, `ExecutorService`, `ReentrantLock` |
| Тесты | `TaxiDispatchSystemTest`, 10 тестов |

## Возможные вопросы преподавателя

**Почему цена хранится как BigDecimal?**  
Чтобы избежать ошибок округления, которые возникают у `double` при денежных расчётах.

**Почему нужен ReentrantLock, если есть база?**  
Блокировка защищает объект водителя в Java, а условие в SQL и транзакция дополнительно защищают данные в базе.

**Почему используется BlockingQueue?**  
Она безопасна для нескольких потоков: один поток добавляет заказ, а диспетчерские потоки забирают его без ручной синхронизации очереди.

**Где используется полиморфизм?**  
`DispatcherService` работает с интерфейсом `PricingStrategy`. Ему можно передать обычную или повышенную стратегию цены без изменения диспетчера.
